# BE-FIT API v3

Base path: `/api/v1`

All responses use:

```json
{"success":true,"data":{},"message":"OK","errors":[],"meta":{}}
```

Authenticated requests use `Authorization: Bearer <token>`.

## Public

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | API + DB health |
| POST | `/auth/login` | Login with email/phone + password |
| POST | `/auth/forgot-password` | Create short-lived password reset token |
| POST | `/auth/reset-password` | Reset password with token |

## Member / admin

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/auth/logout` | Revoke current token |
| GET | `/auth/me` | Current user, including `must_change_password` |
| GET | `/profile` | Profile |
| PUT | `/profile` | Update contact/profile |
| PUT | `/profile/password` | Change password and revoke all tokens |
| GET | `/schedule/week?date=YYYY-MM-DD` | Weekly schedule, booking/waitlist state |
| GET | `/bookings?from=&to=` | Own booking history/upcoming |
| POST | `/bookings` | Book `{ "session_id": 123 }` |

| POST | `/waitlist` | Join full session `{ "session_id": 123 }` |
| DELETE | `/waitlist/{id}` | Leave own waiting-list entry |

| GET | `/announcements` | Active announcements |
| GET | `/payments` | Own membership payment status + history |

## Booking rules

Member booking is controlled by settings and enforced by the backend:

- `booking_days_ahead`
- `booking_cutoff_minutes`
- `cancellation_cutoff_minutes`
- `waitlist_enabled`
- `auto_promote_waitlist`

There is no maximum-active-bookings or per-day booking quantity limit. Administrator-created bookings still cannot overbook a session or book a closed/past session.

## Administrator

Existing admin endpoints remain available for users, schedule templates, dated sessions, closures, bookings, announcements and settings.


### Member payment validation

Payment is validated by an administrator; there is no online card/payment gateway. An expired or missing payment **does not block bookings**.

Member:

`GET /payments`

returns `status` (`paid`, `expired`, `unpaid`), `paid_until` and payment history.

Administrator:

- `GET /admin/users/{id}/payments`
- `POST /admin/users/{id}/payments`

Example:

```json
{
  "payment_date": "2026-09-18",
  "valid_until": "2026-10-18"
}
```

Both dates are optional on POST. If `valid_until` is omitted, the API extends an active membership by one calendar month; otherwise it starts one month from the payment date. The admin may override the proposed date. Payment history stores the confirming admin.

`GET /admin/users` and `GET /admin/users/{id}` also include `payment_status` and `paid_until`.

### Attendance

`PATCH /admin/bookings/{id}/attendance`

```json
{"status":"checked_in"}
```

Allowed: `booked`, `checked_in`, `no_show`.

### Active waiting list

`GET /admin/waitlist?from=YYYY-MM-DD&to=YYYY-MM-DD&status=waiting`

Returns member/session details ordered by session date/time and the time each member joined the queue. `status` may be `waiting`, `promoted`, `left`, or empty for all statuses.

### Attendance report

`GET /admin/reports/attendance?from=YYYY-MM-DD&to=YYYY-MM-DD`

Returns totals, average occupancy, most popular hour and daily rows.

### Member notifications

In-app notifications are created for booking confirmation/cancellation, automatic waiting-list promotion, dated session changes/cancellation, full-day gym closures, and optional next-day reminders generated by `php bin/create-reminders.php`.

A dated session set to `cancelled` automatically cancels active reservations and releases its waiting list. A full-day closure does the same for sessions on that date. A session set only to `closed` blocks new reservations but keeps existing reservations.

### V3 settings

`PUT /admin/settings`

```json
{
  "gym_name":"BE-FIT TRAINING CENTER",
  "default_capacity":8,
  "show_attendee_names":false,
  "booking_days_ahead":30,
  "booking_cutoff_minutes":60,
  "cancellation_cutoff_minutes":120,
  "waitlist_enabled":true,
  "auto_promote_waitlist":true
}
```

## Status codes

- 200 success
- 201 created
- 401 unauthenticated
- 403 inactive/insufficient role
- 404 missing resource
- 409 booking/business conflict
- 422 validation error
- 429 rate limited
- 500 unexpected error
